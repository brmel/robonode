# Architecture audit — 2026-07-15 (pre-implementation)

> Full read of the seams, class designs, sync/async, inter-module flow, user journeys, and file layout **before** the Phase-R/implementation work (#34+) churns them. The codebase is clean and the seams are genuinely good — these are the improvements to make *first*, so the implementations fill interfaces instead of breaking them. Evidence is `file:line`. Each finding → improvement → issue.

## Verdict

Structurally sound: one error model, descriptor-driven, boundary-lint-enforced isolation, real seams (`AxisAdapter`/`Kinematics`/`Planner`/`SetpointSource`/`DriverRegistry`/`CellGateway`). One real bug (F1), and five interface/model widenings that are far cheaper to do *before* the engines land than after.

## Findings

### F1 — BUG: swapping the MuJoCo clock-owner node freezes physics (P0) → #50
- **Evidence:** `MujocoWorldPool::get` hands `clock_owner=true` to the *first* adapter per world path ([mujoco_driver.hpp:42](../sim-mujoco/include/robonode/sim_mujoco/mujoco_driver.hpp#L42)); only that adapter steps physics ([mujoco_axis_adapter.hpp:50-52](../sim-mujoco/include/robonode/sim_mujoco/mujoco_axis_adapter.hpp#L50-L52)). `Cell::replace_node` rebuilds an adapter via the registry ([cell.hpp:56-75](../celld/include/robonode/celld/cell.hpp#L56-L75)).
- **Failure:** swap the clock-owner node (rail-x) to `sim-axis` → nobody steps the shared world → the other 6 physics joints freeze. The exact "try each version" journey the platform is built on, on the exact node the demo lists first.
- **Improvement:** stepping the physics world is a **cell/executive responsibility, not an adapter's identity**. Give `SyncExecutive` an explicit list of "world ticks" (steppables) it advances once per cycle in the step phase, decoupled from which adapters exist. World stepping survives any swap.

### F2 — The executive is one-shot; the interactive vision needs a continuous, command-driven loop (High) → #51
- **Evidence:** `Executive::execute(source, rows, run_for_s)` and `SyncExecutive::execute(plan, ...)` run `n_cycles` then **return** ([executive.hpp:36-92](../motion/include/robonode/motion/executive.hpp#L36-L92), [sync_executive.hpp:57-134](../motion/include/robonode/motion/sync_executive.hpp#L57-L134)). The gateway worker calls `run_move()` which **blocks** the worker for the whole run ([cell_gateway.hpp:186-203](../gateway/include/robonode/gateway/cell_gateway.hpp#L186-L203)); commands enqueued during a run wait.
- **Why it matters:** jog (#22), mid-flight retarget, Tier-B algo-in-the-loop (#26), and live CLI/agent control all require injecting setpoints/commands **cycle-by-cycle from outside** a running loop. Today you can only submit whole runs. This is the structural blocker for the interactive/agent story — and the natural home for the lock-free SPSC (#35).
- **Improvement:** a persistent `CellExecutive` that runs continuously and, each cycle, drains a command/setpoint SPSC (jog, retarget, swap, algo output) → govern → step → telemetry SPSC out. One-shot `run_waypoints` becomes "load a plan as the active source." Do this **before** #26/#22/#35 implementation.

### F3 — Kinematics seam is position-only; Pinocchio (#34) forces SE(3) (High) → #52
- **Evidence:** `Kinematics` exposes `tcp_position()`→`Vec3` + `position_jacobian()`→3×dof ([kinematics.hpp:24-29](../motion/include/robonode/motion/kinematics.hpp#L24-L29)); IK/moveL/jog are all position-only ([cartesian.hpp](../motion/include/robonode/motion/cartesian.hpp)); `Goal` carries `Vec3` only ([planner.hpp:21-25](../motion/include/robonode/motion/planner.hpp#L21-L25)); `geometry.hpp` has `Vec3` only.
- **Why:** Pinocchio (#34) brings full SE(3) FK + 6×dof Jacobian + orientation IK. Landing it against a position-only seam breaks `Kinematics`, `cartesian.hpp`, `Goal`, `CartesianLinePlanner`, and every caller.
- **Improvement:** widen the seam **now** — add `Quat`/`Pose`/`Twist` to `core/geometry.hpp`, add `tcp_pose()` + full `jacobian()` (6×dof) + orientation to `Goal`. v0 impls fill position only (orientation identity); #34 becomes a fill-in, not an interface break.

### F4 — Unitless core types: the `_mm` suffix lies for rotary joints (High, cross-cutting) → #53
- **Evidence:** `State` is unitless ([state.hpp:8-12](../core/include/robonode/core/state.hpp#L8-L12)) but `AxisState`/`AxisLimits`/`TelemetryRow`/`Governor::Result` are all `_mm`-suffixed ([state.hpp:19-23](../core/include/robonode/core/state.hpp#L19-L23), [limits.hpp:8-14](../core/include/robonode/core/limits.hpp#L8-L14), [telemetry.hpp:10-18](../core/include/robonode/core/telemetry.hpp#L10-L18)) — yet a joint stores **radians** in `position_mm`. The design says "units travel in the descriptor, not the type" ([state.hpp:5-7]) — the field names violate their own rule.
- **Why:** every joint's telemetry is mislabelled mm; the hazard spreads as Pinocchio/SE(3) (all SI) lands, and it makes the code lie to every reader and agent.
- **Improvement:** drop the `_mm`/`_mm_s` suffixes → unitless (`position`, `velocity`, `velocity_max`, …) matching `State`. Mechanical rename across core+motion+celld+gateway+tests. Do it **before** #34 so new modules inherit clean names.

### F5 — Version-swap exists only for axes; the MIL promise needs a Module registry (High) → sharpens #30
- **Evidence:** `DriverRegistry` maps name→`AxisAdapter` factory only ([driver_registry.hpp:24-64](../motion/include/robonode/motion/driver_registry.hpp#L24-L64)). `Kinematics`/`Planner` are constructed directly (e.g. [planner.hpp:55-58](../motion/include/robonode/motion/planner.hpp#L55-L58)) — no version list, no live-swap. Lifecycle is inconsistent: `AxisAdapter : LifecycleParticipant` but `Kinematics`/`Planner`/`SetpointSource` have none.
- **Why:** "try each version of a node" (the MIL promise) is real only for MotionAxis. Kinematics/Planner/Vision have no gallery, no swap, no lifecycle.
- **Improvement (fold into #30):** generalize to a `ModuleRegistry` keyed by (capability, version) with a uniform factory + lifecycle; `DriverRegistry` becomes `ModuleRegistry<MotionAxis>`. Define a common `Module` base (lifecycle + capability id + version) all capabilities implement, or explicitly mark the pure-function ones. This is what makes #47 (version-manager UI) real for every capability.

### F6 — Planner returns bare waypoints; cuRobo/Crocoddyl produce timed trajectories (Medium) → #54
- **Evidence:** `Planner::plan` returns `waypoints[joint][step]` ([planner.hpp:30-31](../motion/include/robonode/motion/planner.hpp#L30-L31)), re-timed by `SyncBlendPlan`.
- **Why:** cuRobo (#39) and Crocoddyl (#41) emit **time-parameterized, dynamically-feasible** trajectories; forcing them through "waypoints → re-time" discards their optimization.
- **Improvement:** richen the Planner output to an optional `PlannedTrajectory` (waypoints **or** timed samples that flow straight into a `SetpointSource`). Simple planners still emit waypoints. Design **before** #39.

### F7 — Error model still mixes throw / Status / out-param at the seams (Medium) → sharpens #36
- **Evidence:** `RtbKinematics` **throws** on failure ([rtb_client.hpp:24-31](../bridges/rtb/include/robonode/rtb/rtb_client.hpp#L24-L31)) while its seam sibling `MujocoKinematics` does not; `SyncExecutive` ctor throws ([sync_executive.hpp:50-52]); value returns use out-params + `Status` ([driver_registry.hpp:51], [planner.hpp:30]). `Cell::run_waypoints` try/catches to convert ([cell.hpp:104-110]).
- **Improvement (fold into #36):** `std::expected<T, Error>` for value-returning seam calls; no throw across a seam; mark offline-only impls (RtbKinematics) so they can't be wired into the loop (the #34 check-design gate).

### F8 — Minor / low
- **App boilerplate:** 6 `apps/*/main.cpp` repeat world-path + registry setup — a small `app_harness` helper would dedup. Low.
- **No curated public header:** consumers include deep paths; the facade (#33) should expose one `robonode/platform.hpp`. Low, tie #33.
- **`trajlib/` lacks the `robonode/` include prefix** — intentional (private profile lib) but inconsistent; document or namespace. Low.

## Recommended reorder (the actionable output)

Interfaces first, engines second — so the P0 engine work fills seams instead of breaking them:

```
BEFORE Phase R engines:  F1 #50 (bug)  ·  F4 #53 (unitless)  ·  F3 #52 (SE3 seam)  ·  F2 #51 (continuous executive)  ·  F5 #30 (module registry)
THEN:                    #34 Pinocchio (fills #52)  ·  #35 SPSC (plugs into #51)  ·  #36 expected (F7)
BEFORE Phase 3 planners: F6 #54 (timed-trajectory Planner)  →  #39 cuRobo  ·  #41 Crocoddyl
```

F1 (#50) is a bug — fix regardless. F3/F4/F53 and F2 are the high-leverage "widen before you fill" items; skipping them means #34/#26 churn every caller twice.
